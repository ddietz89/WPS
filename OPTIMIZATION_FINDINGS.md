# WPS optimization: findings and proposed next steps

Updated 12 October 2026 UTC. This is the consolidated report; it supersedes older candidate promotion decisions, while preserving the scope of their original measurements.

## Current outcome

The private WPS fork includes the six earlier source improvements, the newly promoted contiguous RRPR bulk read, RH row parallelism and independent decoder scaling threads, a four-thread Ungrib default, a qualified WRF I/O identity dependency package, bounded root packing scratch reuse, the compatible zlib-ng launcher, the default MPI compression backend and Metgrid row interpolation threads for qualified MPI/NetCDF builds. Metgrid defaults to four threads per rank and reduced stage wall time by a median 11.94% in three matched pairs, using 22.01% more CPU. Several other changes accelerate isolated kernels without a large or repeatable whole-stage gain.

The earlier combined configuration passed fresh short integration, including both rebuilt users of the shared interpolation source. All seven qualification products and all 28 products from four matched timing runs pass the pinned exact science and output-layout checks. The fresh 25-time pipeline also passes all 51 products. The separate five-time, three-hour cadence case passes all 11 products; the native 49-time combined case passes all 99 products against its independently established reference; a two-minute full-grid forecast resource probe completed. Historical timings below retain their original configuration scope.

Production `/pool/wrf/WPS` remains a read-only reference. No production source or original scientific checker has been changed.

The latest combined working package passed all 28 products in two reversed representative pipeline pairs, with median **7.93% less wall time and 7.16% less CPU** against the previous working defaults. This includes the new Ungrib scaling, WRF identity writes and root packing scratch cache; later experimental header/MPI in-place paths are excluded. Earlier 25/49-time pipeline and downstream results retain their original build scope. This incremental result is separate from the earlier 23.95% comparison and must not be added to it.
